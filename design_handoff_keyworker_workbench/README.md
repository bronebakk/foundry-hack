# Handoff: Northgate Futures — Keyworker Workbench (refined UX)

## Overview

The **Keyworker Workbench** is an AI augmentation layer for frontline keyworkers who re-engage
NEET young people (16–24 not in education, employment or training). It synthesises a young
person's fragmented history into a pre-meeting **context brief**, drafts case notes and
follow-ups **in the worker's own voice**, and surfaces risk/follow-up signals — **always as
editable proposals the human authors and commits, never as autonomous actions.**

The one idea the whole UI must make obvious within ~60 seconds:

> **The AI proposes. The human disposes.** On sovereign, open-weight infrastructure, with
> **synthetic data only.**

This handoff covers the **refined ("after") UX** — a craft/hierarchy pass over the existing
build. The product is six surfaces forming one narrative arc, carried by a single young person.

---

## About the design files

The files in `design-files/` are **design references created in HTML/React-via-Babel** —
prototypes that show the intended look and behaviour. **They are not production code to copy
directly.** Your task is to **recreate these designs in the target codebase's environment** using
its established patterns and libraries.

> **Target environment for Northgate Futures:** the live product is **Python FastAPI +
> server-rendered Jinja2 templates + HTMX + Pico.css + SQLite** — *no SPA framework, no build
> step.* The React in these prototypes is **only a prototyping convenience**; reimplement as
> **semantic HTML in Jinja partials + a thin CSS layer + HTMX partial swaps**. Everything must
> degrade gracefully without JS and render fast on a Chromebook over poor wifi. Do **not**
> introduce Tailwind, a JS build pipeline, or megabyte bundles.

The single source of truth for visual tokens is **`design-files/kit-refined.css`** (the refined
"after"). `colors_and_type.css` is the brand token layer it derives from.

## Fidelity

**High-fidelity (hifi).** Final colours, typography, spacing, radii, and interactions are all

codebase's HTML/CSS. Where this prototype uses React state, the production app uses HTMX partial
swaps — match the *visual result and the governance reading*, not the React mechanics.

## The seven Hard Invariants (non-negotiable — they drive the UI)

A beautiful implementation that erodes any of these is a **failed** implementation.

1. **AI proposes, human disposes — and it must be _visually obvious_.** Every AI output reads
   unmistakably as an *uncommitted, editable draft* (the dashed proposal frame), with the human
   action (Commit / Send / Escalate / Discard) as the deliberate next step.
2. **The worker is the author of record;** the AI is a drafting assistant. Never label the
   record "generated by AI". Copy: "you are the author of record", "your words are what gets
   committed".
3. **No "computer says no".** The system never *denies* anything. A refusal-shaped moment gets a
   reason + a real alternative + a **named human** (the blue options surface).
4. **Safeguarding is human-owned.** Risk is *surfaced for judgement, never acted on
   automatically.* Escalation is human-initiated into a human-owned queue the machine never
   marks "resolved". Calm, never red-alert.
5. **Explainability.** Every claim/signal traces to its **source record** (the "Says who?" chip).
6. **Synthetic data, always — and visibly.** The yellow synthetic banner is persistent and
   unmissable.
7. **Open-weight / sovereign.** Runs on a self-hostable open-weight model
   (`openai/gpt-oss-120b`, fallback `meta-llama/llama-3.3-70b-instruct`). Keep provenance
   inspectable; never imply a closed cloud AI.

- Spacing rhythm is `0.25rem`-based; common paddings: cards `1.2rem 1.3rem`, callouts

## Screens / Views

The app is six surfaces. A persistent **synthetic banner** sits above everything; a **sticky top
bar** (logomark + wordmark + nav) is always present; person-scoped surfaces (Context, Drafting,
Safeguarding) also show the **person-arc stepper**.

### Global chrome

**Synthetic banner** (`.synthetic-banner`) — full-width, `--synth-bg` on `--synth-text`, 1px
`--synth-border` bottom, centered, `0.8rem`/600. Text: `🧪 SYNTHETIC DEMO DATA — every persona
and record is fictional. No real people, no real client data.` Always present.

**Top bar** (`.topbar`) — sticky, `backdrop-filter: blur(8px)`, translucent `--page` bg, 1px
`--hair` bottom.
- **Logomark** (`.brand .mark`) — a minimal 28×28 "gate/threshold" SVG: a rounded square
  (`--accent-soft` fill, `--accent` stroke) containing an arch (two uprights + a curved lintel)
  and a centre post. It is the *only* SVG drawn in the system. Keep it understated; an
  equivalent simple wordmark-with-mark is fine.
- **Wordmark** — "Northgate Futures" (`--ink`, 700, `-0.02em`) + a `--muted` "Keyworker
  Workbench" descriptor divided by a hairline (hidden < 560px).
- **Nav** (`.nav-links a`) — pill links; hover fills `--inset`; active fills `--accent-soft`
  with `--accent` text, 600. Items: Caseload, Context, Drafting, Safeguarding, Decision log.

**Person-arc stepper** (`.arc`) — sticky (top 53px), white pill, `--shadow`, 1px `--hair`.
- Left: `.arc-who` — person name + age + `synthetic` tag, 700 `--ink`.
- Right: `.arc-steps` — four steps (1 Context › 2 Drafting › 3 Safeguarding › 4 Decision log).
  Each `.arc-step` is a pill with a numbered circle (`.n`, 1.25rem, `--inset`/`--muted`); the
  **active** step fills `--accent-soft`/`--accent` and its circle goes `--accent`/white. `›`
  chevrons between. `aria-current="step"` on the active one.
- < 720px: collapses to a stacked, non-sticky block; step labels hide, numbered dots remain.

**Footer** (`.app-footer`) — 1px `--hair` top, `--muted`, `0.85rem`. Text: "The AI **proposes**;
the worker **disposes**. Open-weight inference (`gpt-oss-120b`), self-hostable. Worker of record:
Sam Ellison (keyworker)."

### 1 · Caseload (`/`)
- **Purpose:** entry point — pick a young person.
- **Layout:** eyebrow ("Your workbench") → `h1` "Your caseload" → `.lead` → a 3-column grid
  (`.grid.cols-3`, 2-col < 880px, 1-col < 600px) of persona cards.
- **Persona card** (`.card.card-hover`, clickable): name (`h3`) + right-aligned age; `synthetic`
  tag; summary line; a footer row with "{n} source records" and either a red **safeguarding
  signal** `.tag-risk.tag-dot` (if any record carries risk) or an "Open" affordance. Hover lifts
  (`--shadow-lift`, `translateY(-2px)`). Clicking → Context for that person.
- **Personas (synthetic):** Amara Okafor 19, Noah Bennett 18, Marcus Fielding 20 (the "no
  computer says no" case), Leah Sumner 16 (safeguarding signal), Ivy Castellano 16 (wellbeing
  signal), Kofi Mensah 17. Full data + source records in `design-files/data.js`.

### 2 · Context (`/context/{id}`)
- **Purpose:** "walk in prepared" — an AI-synthesised brief where every claim traces to a source.
- **Layout:** eyebrow ("Walk in prepared") → `h1` "Context — {name}" → `.lead` → **proposal
  frame** (variant: header pill reads "⬩ Brief", meta "Pre-meeting synthesis — not a record of
  truth") containing a `.brief-list` of statements → `h2` "Source records ({n})" → record cards.
- **Statement** (`.ctx-statement`): claim text, then a `.says-row` with a `.says-who` "Says who?"
  label + a `.source-link` chip (`↳` prefix, `--accent-soft` pill). Clicking the chip
  smooth-scrolls to the matching `.record` and flashes it (`.record.flash` → `--accent` border +
  `--accent-soft` 3px ring, 1.8s).
- **Record card** (`.record`): source + date + author in `.rec-head` (+ red `safeguarding signal`
  tag if `risk`), then a `blockquote` of the verbatim record text.

### 3 · Drafting (`/drafting/{id}`) — **HERO SURFACE**
- **Purpose:** the propose→dispose moment. The single most important screen.
- **Layout:** eyebrow ("The propose → dispose moment") → `h1` "Drafting for {name}" → `.lead` →
  2-col grid: "Draft a case note" (textarea for optional meeting notes + primary **Draft case
  note** button) and "Draft a follow-up message" (copy + ghost **Draft follow-up message**
  button). On generate → the **proposal frame** appears below. Then a 2-col grid of "Committed
  case notes ({n})" and "Sent messages (0)" ledgers.
- **PROPOSAL FRAME** (`.proposal` — the hero component):
  - Container: `1.5px dashed --proposal`, `--r-lg`, `--proposal-bg`, **no shadow**,
    `overflow:hidden`.
  - **Header** (`.proposal-head`): a diagonal hatched strip (`repeating-linear-gradient(135deg,
    #eef0ec 0 8px, #f4f5f2 8px 16px)`), `1.5px dashed --proposal` bottom, containing a
    `.proposal-pill` ("⬩ Draft", `--ink` bg, white, uppercase, pill) + meta ("Case note · not
    committed, nothing sent").
  - **Body** (`.proposal-body`): meta line "Drafted by open-weight model (`gpt-oss-120b`) · **you
    are the author of record**." → a `label` "Your version — edit freely; your words are what
    gets committed" wrapping a `textarea` prefilled with the AI draft → `.proposal-actions`.
  - **Actions** (`.proposal-actions`): weighted. **Commit as my note** = `.btn-ink.btn-lg`
    (heavy); **Discard** = `.btn-ghost` (quiet). On Safeguarding/NoDeny the heavy action is
    `.btn-contrast`.
  - **Foot** (`.proposal-foot`): "⬩ The AI drafts; you decide. Nothing is saved and nothing is
    sent until you choose an action above."
- **Behaviour:** Commit → prepends a `.committed-record` (green, "✓ Committed by Sam Ellison
  (keyworker) · date") to the ledger **and appends an entry to the Decision log**. Discard → frame
  disappears, nothing saved. In production these are HTMX `POST`s that swap the frame for the
  committed record and append to the log.

### 4 · Safeguarding (`/escalation/{id}`)
- **Purpose:** surface a risk flag for human judgement; let the worker escalate.
- **Layout:** eyebrow ("Surfaced for your judgement · human-owned") → `h1` "Safeguarding —
  {name}" → `.lead` → italic demo note → **callout** (`.callout`, amber, 🛡️ icon): "**No
  automatic action has been or will be taken.** … **You decide what happens next.**" → `h2`
  "Surfaced signal" → **risk card**.
- **Risk card** (`.risk`, `--risk` 4px left border, `--risk-bg`): risk category title + red
  `safeguarding signal` tag; "Why this was flagged" rationale; an embedded `.record` showing the
  triggering source ("Source — record `leah-r2` — this is what triggered the signal"); then
  "Escalate — your decision" with the **proposal frame** (escalation note draft; heavy action =
  **Escalate to safeguarding lead** `.btn-contrast`, quiet = "Not now — record my review").
- **Behaviour:** Escalate → green `Receipt` ("Sent to the safeguarding inbox. It arrived because
  **you** chose to send it…") + appends a `risk_flag` escalation to the log/inbox. "Not now" →
  neutral receipt, nothing sent.
- If a persona has no risk record, show a calm "No safeguarding signal is present" callout
  instead.

### 4b · Options — "no computer says no" (Marcus Fielding)
- **Purpose:** the warm refusal pattern (Invariant 3). Routed when a persona is flagged `noDeny`.
- **Layout:** eyebrow ("No computer says no") → `h1` "Options — {name}" → the young person's own
  words in a blue-bordered blockquote → **option card** (`.option`, `--info` 4px left border,
  `--info-bg`): a `.no-no` panel ("**The system isn't telling Marcus Fielding 'no'.** It can't —
  and it won't…"), then the **proposal frame** (hand-off note; heavy action = **Send to a
  keyworker to decide** `.btn-contrast`).
- **Behaviour:** Send → green receipt ("Handed to a keyworker…") + appends to the log.

### 5 · Safeguarding inbox (`/escalation/inbox`)
- **Purpose:** a human-owned queue; the machine resolves nothing.
- **Layout:** eyebrow ("A human-owned queue") → `h1` "Safeguarding inbox" → `.lead` →
  `.inbox-owner` strip ("👤 Owned by **Safeguarding Lead (human)** · the machine marks nothing
  'resolved'.") → list of `.queue-item`s.
- **Queue item** (`.queue-item`, neutral or `.escalate` red left border): header with a tag
  (`safeguarding escalation` red, or `decision needed (human)` blue) + person name + date; an
  `.arrived` line ("↳ Arrived because **Sam Ellison (keyworker)** sent it. Not auto-generated.");
  the note blockquote; and `.q-status` ("● Awaiting human review · a person decides and resolves
  this — the system will not."). Items are populated by escalations sent from surface 4/4b.

### 6 · Decision log (`/governance/`) — **SHOWCASE SURFACE**
- **Purpose:** the append-only governance spine judges linger on. Each entry must scan as
  *AI proposal → human disposition → worker of record* at a glance.
- **Layout:** eyebrow ("The governance spine") → `h1` "Decision log" → `.lead` →
  `.gov-immutable` lock banner (green: "🔒 **Append-only.** … there is no edit or delete control
  to find.") → `.gov-inference` provenance strip (open-weight model names) → `.gov-filter` chips
  (All + per-person; active = `--accent` filled pill) → "{n} entries · newest first." → the log.
- **Log entry** (`.gov-entry`, 4px left border tinted by disposition: commit=green, send=blue,
  escalate=red, discard=grey; `--shadow`):
  - `.gov-head`: mono `#N` id, a disposition **badge** (`.badge.badge-{disposition}`, uppercase
    pill with a leading dot), right-aligned tabular timestamp.
  - `.gov-meta`: "{person} · surface: {surface} · {type}".
  - `.gov-flow`: two stacked boxes with a `↓` connector — `.gov-step.ai` (muted inset, label
    "⬩ AI PROPOSED", proposal text) → `.gov-step.human` (green, label "→ Sam Ellison (keyworker)
    {verb}", final committed/escalated text). This two-box split is the key readability move.
- **Seeded entries:** two escalations (Marcus follow-up, Leah risk flag). Commits/escalations
  from other surfaces append live (newest first), filterable by person.

## Interactions & behaviour
- **Navigation:** top-bar nav routes to any surface; the person-arc stepper routes within one
  person's arc; persona cards open Context; "Continue to drafting →" / back-links move along the
  arc. In production: server routes + HTMX `hx-get` for partial swaps.
- **Generate (Draft / Brief / Escalation note):** reveals the proposal frame prefilled with model
  output. Production: `hx-post` returns the frame partial. Show a quiet "drafting…" text indicator
  while in flight — **never** a heavy spinner overlay.
- **Dispose (Commit / Send / Escalate / Discard):** the deliberate human action. Commit/Send/
  Escalate persist + append to the decision log and swap the frame for a confirmation receipt;
  Discard removes the frame with no persistence.
- **Source attribution:** clicking a "Says who?" chip smooth-scrolls to the source record and
  flashes it (`:target` in production — no JS needed, per the existing app).
- **Transitions:** subtle only — `0.12–0.25s ease` on background/box-shadow/transform; card
  hover-lift `translateY(-2px)`. **No bounces, no decorative motion.** Respect
  `prefers-reduced-motion: reduce` (the CSS already disables transitions under it).
- **Focus:** `:focus-visible` shows a 3px ring (`--info-border`, or `--accent` on buttons).
  Keyboard-navigable throughout.

## State management
- `route` (which surface) and `pid` (selected persona id) — in production these are URL routes
  (`/context/{id}` etc.), not client state.
- `log` — the **append-only** decision-log collection. Seeded with two escalations; Commit/
  Escalate/Send **append** (never edit/delete — enforced at DB trigger + service layer). Inbox is
  a filtered view of escalation entries; Decision log is the full list, filterable by person.
- Per-surface ephemeral UI state: whether a draft frame is shown, the editable textarea value,
  and post-disposition receipts.
- **Data fetching:** AI proposals come from an OpenAI-compatible open-weight inference provider
  (`openai/gpt-oss-120b`, fallback `meta-llama/llama-3.3-70b-instruct`). No closed cloud model.

## Assets
- **Logomark:** the only drawn asset — a minimal inline "gate/threshold" SVG in
  `components.jsx` (`Mark`). Reproduce as inline SVG or a small static file; keep it understated.
- **No photography, illustration, gradients, or icon font.** Glyphs used are Unicode only: `⬩`
  (proposal eyebrow), `↳` (source / arrived), `→`/`↓` (disposition), `›` (stepper), `🧪`
  (synthetic), `🔒` (append-only), `🛡️`/`👤` (callout/inbox accents — optional, may be dropped
  for a stricter no-emoji stance). If richer icons are ever needed, use a thin-stroke monoline set
  (e.g. Lucide) sparingly.
- **Font:** Public Sans (self-host woff2 in production) or fall back to system-sans.
