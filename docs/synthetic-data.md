# Synthetic data — provenance & how-to

*Anchors Invariant 3 (synthetic data only) and Invariant 7 (explainable flags). This is a
**demo asset**: it lets us tell the governance story cleanly — we never touch real NEET
data, and even our test data is generated by an open-weight model on our own infra.*

## Provenance (the honest answer for a judge)

- **Every persona and record in this repo is entirely fictional.** No real person, no
  scraped data, no real client material. Names are assembled from generic pools; any
  resemblance to a real individual is coincidental and unintended.
- **Two kinds of data, kept apart:**
  - **Hero personas** (`app/data/personas/`, plus staged additions in
    `app/data/personas_staged/`) — hand-curated for the demo narrative, voiced to read like
    real case notes.
  - **Bulk / edge fixtures** (`tests/fixtures/personas/`) — machine-generated for tests and
    load, with `gen-…` ids that visibly mark them as generated.
- **Every persona carries `synthetic: true` and a fictional `demo_note`,** and must pass the
  automated synthetic-data gate (below) before it ships.

## The gate — `scripts/validate_personas.py`

A persona **fails** the gate (non-zero exit) if it is not visibly synthetic, has an
unexplained risk flag, has duplicate or anchor-unsafe ids, a non-ISO date, or empty record
text. Run it over any directory:

```bash
python -m scripts.validate_personas app/data/personas app/data/personas_staged
python -m scripts.validate_personas tests/fixtures/personas
```

Key rules enforced:
- `synthetic: true` is **required** (Invariant 3) — a non-synthetic persona is a hard error.
- A record with `risk_indicator: true` **must** carry `risk_category` + `risk_rationale`
  (Invariant 7 — no flag without a reason).
- Persona ids are URL-safe and record ids are HTML-`#anchor`-safe, so the CTX brief's
  source-linking (VAL-CTX-002) can never dangle.

## The generator — `scripts/generate_personas.py`

Hybrid: deterministic by default, open-weight LLM opt-in. Everything it emits is gated
before writing.

```bash
# Deterministic bulk + edge fixtures (no API key needed; reproducible by seed)
python -m scripts.generate_personas --count 12 --seed 42 --edges --out tests/fixtures/personas

# Open-weight LLM drafts (opt-in; Invariant 4 — gpt-oss-120b / Llama fallback)
python -m scripts.generate_personas --llm --count 3 --out app/data/personas_staged

# Validate-only, write nothing
python -m scripts.generate_personas --count 20 --dry-run
```

**Edge cases** (always available via `--edges`): zero-record, single-record, very long
text, multi-risk, unicode, minimal-fields — the inputs that break renderers and routes.

## Inference key (LLM mode)

The OpenRouter key (a cost stand-in for self-hosted vLLM — decision D-002) is read from the
`OPENROUTER_API_KEY` env var, falling back to a **git-ignored** `orkey.txt` at the repo root.
For the running app, export it:

```bash
export OPENROUTER_API_KEY="$(cat orkey.txt)"
uvicorn app.main:app --port 8000
```

`orkey.txt`, `.env`, and `*.key` are git-ignored — the key is never committed.

## Merging staged personas (coordination note — see decisions.md D-005)

`app/data/personas/` is a frozen shared resource read by the live M3/M4/M5 streams, and a
foundation test asserts an exact persona count. New hero personas are therefore **staged**
in `app/data/personas_staged/` and merged into the live set at the **M6 integration** step,
updating the count assertion then — not mid-stream.
